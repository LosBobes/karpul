# Operations: backups, the paper-log backfill, health, monitoring, the country filter

Moved out of CLAUDE.md, which keeps a one-line pointer here. These are the
feature notes for working on this part of Karpul: the rules, where they live
and why. Keep them in step with the code like CLAUDE.md itself.

Server operations from a laptop (needs `HETZNER_HOST` / `HETZNER_USER` in the shell): `make ssh`, `make logs`, `make deploy`, `make backup`, `make backups` (the app's own nightly snapshots, below), and `make backfill` (the shared Mazda's 2026 paper log as rides, `app/backfill.py`; a dry run unless `APPLY=1`, safe to repeat). Nobody needs to run it: the lifespan calls `backfill.run_once` on every start, which applies it once and records `mazda-log-2026` in the `DataMigration` table so it never runs again (with no single Mazda in the pool it logs a warning, writes nothing and tries again on the next start; a failure is logged and never stops the app). **A coming log ride takes nobody until its driver confirms it**: the log says who booked the car, not that they offer seats, so the backfill writes days from today on with `Ride.unconfirmed` (an `ADDED_COLUMNS` column) and `backfill.hold_once` (marker `mazda-log-2026-unconfirmed`, run on start after it) marks the coming log rides written before that existed and still on the log's own times (`backfill_notice.needs_a_look`); whoever already sits in one stays. While it is set, `join_ride` and the waiting list are a 409 for anyone but whoever runs the ride (`may_run`); `POST /api/rides/{id}/confirm` (driver or admin, `ride_confirmed` in the admin's log) or any edit by the driver clears it. On screen: a *Not confirmed* tag on the card and the Upcoming row, a `.approval-row` with *Confirm the ride* for whoever runs it and the reason for everyone else, and `hasSeatFor` in `lib/me.ts` keeps it out of *Free seats*, the drop targets and the tray. Right after it, once and only while push is on, `backfill_notice.run_once` pushes the people best placed to look at those rides (`app/backfill_notice.py`, marker `mazda-log-2026-notice`, category *reminders*): `log_yours` to an account driving log rides that still hold a guess (a coming one on the log's 08:00–18:00, a driven one with no odometer), `log_claim` to the account whose name is most like a log name with no account (`name_likeness` in `services.py`, at least `SIMILAR_NAME`), opening a ride where *This is me* waits; one push per person per reason. `python -m app.backfill_notice` is a dry run listing them. Tests: `tests/test_backfill_notice.py`. The backup streams `python -m app.backup`, a consistent snapshot through SQLite's backup API — the database is in WAL mode, so copying `karpul.db` alone loses the latest commits. **The app also backs itself up** (`app/housekeeping.py`, started in the lifespan): once a day the same snapshot goes to `KARPUL_BACKUP_DIR` (default `backups/` beside the database file, in production the volume) as `karpul-<date>-<time>.db`, written under a `.part` name and renamed, the newest `KARPUL_BACKUP_KEEP` (14) kept; the same hourly pass purges expired sessions and spent reset links (`auth.purge_expired`). Nothing runs on an in-memory database. **Off the box**: with `KARPUL_BACKUP_S3_URL` (endpoint, bucket, prefix, path-style) plus `_KEY` / `_SECRET` / `_REGION`, the newest snapshot is also PUT to S3-compatible object storage (`app/offsite.py`, Signature Version 4 on the standard library like `webpush.py`, held to AWS's own example; `offsite.put` is what tests replace and `clean_env` clears the variables). A snapshot that went up gets a `<name>.sent` marker beside it, so a failure is retried on the next pass; the key needs write only, retention is the bucket's lifecycle rule. `housekeeping.backup_status` (`backup`: ok / stale past `BACKUP_STALE` 26 h / off; `offsite`: ok / pending / failing / off) is in `/api/health`. Tests: `tests/test_housekeeping.py`, `tests/test_offsite.py`.

**Operations.** `/api/health` queries the database (503 when it cannot) and carries
`backup` / `offsite` from `housekeeping.backup_status` (never an error; the uptime workflow reads them). `KARPUL_SENTRY_DSN`
turns on Sentry (`app/monitoring.py`, no PII, traces only with `KARPUL_SENTRY_TRACES`); unset sends
nothing. A middleware in `main.py` logs 5xx answers, crashes (then re-raises, for Sentry) and
requests slower than 1 s under `karpul.http`; uvicorn's access log has the rest.
`KARPUL_ALLOWED_COUNTRIES` (`DE,RS`) is a country filter in front of everything, socket included
(`app/geofence.py`, pure ASGI, the outermost middleware): another country is a 403 or a 4403 close,
private addresses always pass, `/api/health` passes from anywhere (`OPEN_PATHS`, for the uptime check on
GitHub's runners), an address the database does not know is refused, and a missing
database logs an error and lets everyone in. The database is DB-IP Lite, downloaded at image build
by `backend/fetch_geoip.py` (it sends its own User-Agent: DB-IP refuses Python's); tests replace
`geofence.country_of`, and `clean_env` clears the variable.
